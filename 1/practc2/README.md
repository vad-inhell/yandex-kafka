
## Классы и компоненты

### Класс `Message`
Модель сообщения с полями `id`, `timestamp`, `payload`.
- `to_json()` — сериализация в JSON
- `from_json()` — десериализация из JSON

### Продюсер (`run_producer`)
Отправляет 50 сообщений с задержкой 0.5 сек.

| Параметр | Значение | Зачем |
| :--- | :--- | :--- |
| `acks` | `all` | Подтверждение от всех ISR-реплик — основа At Least Once |
| `retries` | `5` | Повторные попытки при сбое |
| `enable.idempotence` | `True` | Защита от дублей при повторной отправке |

### SingleMessageConsumer (`run_single_consumer`)
Читает **по одному** сообщению с автокоммитом.

| Параметр | Значение | Зачем |
| :--- | :--- | :--- |
| `group.id` | `single-consumer-group` | Уникальная группа |
| `enable.auto.commit` | `True` | Автокоммит после каждого poll() |
| `auto.offset.reset` | `earliest` | Чтение с начала при отсутствии оффсетов |

### BatchMessageConsumer (`run_batch_consumer`)
Читает **пачками по 10** сообщений с ручным коммитом.

| Параметр | Значение | Зачем |
| :--- | :--- | :--- |
| `group.id` | `batch-consumer-group` | Вторая уникальная группа (читает те же сообщения) |
| `enable.auto.commit` | `False` | Ручной коммит после обработки пачки |
| `fetch.min.bytes` | `1024` | Брокер накапливает минимум 1 КБ перед ответом |
| `fetch.wait.max.ms` | `3000` | Максимум 3 сек ожидания накопления |

**Важно:** оба консьюмера имеют **разные `group.id`**, поэтому читают **одни и те же** сообщения независимо (паттерн Publish-Subscribe).

### Точка входа
Запускает продюсера и обоих консьюмеров **параллельно** в отдельных потоках через `threading`.

docker compose logs -f kafka-app
